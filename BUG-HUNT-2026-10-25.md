## Findings, most severe first

### 1. CRITICAL — The Worker serves the OLD v1 UI
The phone shows tabs *Dashboard · Guests · RSVP · Logistics · Hospitality* (v1 `SECTIONS`), not the
v2/v3 bar (*Dashboard · RSVP · Hospitality · Logistics · Control*).
`src/proxy.ts` only rewrites to `/v2` when `NEXT_PUBLIC_UI === 'v2'`. On Vercel that variable was set
for Production only. `scripts/cf-build.mjs` requires just the two Supabase vars,
`wrangler.jsonc` has no `NEXT_PUBLIC_UI`, and the compiled middleware reads it at runtime
(`.open-next/middleware/handler.mjs`), where it is unset.
**Fix:** build with `NEXT_PUBLIC_UI=v2` (add it to `REQUIRED` in `cf-build.mjs`) and also set it as a
Worker var (the middleware reads `process.env` at runtime). Redeploy; no APK rebuild needed.
Findings 5–7 are v1-only and go away with this fix.

### 2. CRITICAL (once v2 is back) — v2 "Call next" screen cannot load
`GET v_rsvp_queue?select=…,locked_by_staff,…` → **400, `42703 column v_rsvp_queue.locked_by_staff does not exist`**.
The screen shows *"Could not load the calling list. Check your connection and try again."* after
3 retries (`src/app/(app)/v2/[eventCode]/rsvp/queue/CallNext.tsx:66`).
Introduced by **`6415806` (7 Oct, latency sweep)**, which replaced `select('*')` with an explicit list.
Root cause is older: `20260808110000_queue_view_staff_lock.sql` added `locked_by_staff` to the view, and
`20260812000000_presence_columns.sql` drops and recreates the view **without it** (its own comment says
the column exists). Seoul is identical, so v2 production on Vercel was broken the same way since 6415806 shipped.
v1 uses `select('*')`, so it gets `undefined` for the lock holder instead of an error.
**Fix:** new migration re-adding `gg.locked_by_staff` to `v_rsvp_queue` (preferred, also restores lock-holder
names), or drop the column from the CallNext select.

### 3. HIGH — Offline page "Try again" never recovers
Wi-Fi + data off → tap a tab → Capacitor `errorPath` shows `offline.html`. With the network restored,
**Try again did nothing twice** (`location.reload()` reloads the local offline page, not the server).
Only a force-stop gets back in, which is exactly what §11c tells staff never to do.
**Fix:** Try again should navigate to the server URL (e.g. `location.replace('<CAP_SERVER_URL>' + last path)`).
Needs an APK rebuild (the file is bundled in the APK assets).

### 4. HIGH — Wrong access code says "Could not reach the server"
`supabase/functions/verify-access-code/index.ts` sets `Access-Control-Allow-Origin` **only on the 200**
(line 235). The 401 (lines 181/192) and 429 (193) have none, so the WebView blocks the response,
`fetch` throws, and `CodeLoginForm.tsx:145` shows the network message. Verified with curl: 401 with no ACAO header.
Consequences: a mistyped code looks like bad Wi-Fi, and the "Too many attempts" message can never show.
**Fix:** add the CORS headers to every response in that function and redeploy it.

### 5. MEDIUM (v1) — Dashboard tab is dead for an event lead
`bottomTabsFor` shows Dashboard to `department === 'management'`, but `(staff)/[eventCode]/page.tsx:67`
redirects every `event_team` user with a department to `rsvp/campaigns`. Tapping Dashboard bounces back to
Auto Dialer, with no feedback. Reproduced 3× on the emulator.

### 6. MEDIUM (v1) — Hardware back exits instead of going home
Back from the Guests tab shows *"Press back again to close EventFlow"*. `NavTracker` (which sets the
landing tab and visit history for `resolveBack`) is mounted in the v2 and admin layouts but **not** in
`(staff)/[eventCode]/layout.tsx`, so `landing` and `previous` are always null.

### 7. MEDIUM (v1) — Opening a guest from the "read-only" Guest List takes the 15-minute RSVP lock
Rows link to `rsvp/status/{groupId}`, which calls `claimGroupForCall` on render. Browsing a guest locks that
family against callers, with no override (§11b). v2 links to the read-only `families/[groupId]` instead.

### 8. LOW — Offline page copy is always "The phone is online but the server did not answer"
It is static HTML, so it says this even with Wi-Fi and data both off. "Nothing you entered has been lost"
is also unconditional, and not true for a typed-but-unsaved form.

### 9. LOW — Offline banner shifts the whole screen down ~35px
It appears exactly when signal drops, so a thumb mid-tap lands on the wrong control (it happened during testing).
An overlay or reserved space would avoid the layout shift.

### 10. LOW — Guest counts disagree between staff and client
SAMPLE2026 has 769 guests, 817 families, **51 families with no guest rows**. The staff list says
"820 guests" (counts the empty families as guests); the client view says "757 families" (drops families
without a head row, the §12 trap). Probably test fixtures, but the staff count should be `guests`, not search rows.

### 11. LOW — Phone number on a guest row looks like a link but is not
It is brand-coloured text inside the row link, so tapping it opens the RSVP screen rather than the dialer.

## Environment problems found along the way
- **ARTEMIS: missing LLM key** in `C:\Users\rebel\artemis\.env`.
- **`C:\Android\adb.exe` is adb 1.0.32** and comes first on PATH. The emulator calls it, and every call
  kills the SDK's 1.0.41 server (`adb server version (32) doesn't match`). Remove it or put
  `%LOCALAPPDATA%\Android\Sdk\platform-tools` first on PATH.
- AVD `eventops_test` has `hw.ramSize = 1536M`. It booted with no network and `com.android.phone`
  crash-looping; it only worked when launched with `-memory 4096 -cores 4`.
